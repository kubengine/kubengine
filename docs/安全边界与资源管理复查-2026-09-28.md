## 优先处理

### S01 · P1 · 延迟清理任务可以删除新建的应用

位置：[删除任务提交](../src/web/api/app.py#L266)、[清理时查找当前记录](../src/web/api/app.py#L116)、[资源互斥](../src/core/orm/task.py#L322)、[集群主键](../src/core/orm/cluster.py#L41)。

任务只保存 `cluster_id`，没有保存创建时的资源唯一标识或预期 Helm release。SQLite 表未启用防止历史 ID 复用的机制。对同一应用重复提交删除后，第一个任务删除记录，新应用可能复用该 ID；另一个延迟执行或恢复的旧任务会查到新应用，并卸载其 release。文件锁只能串行化操作，不能区分同一个 ID 的两代资源。

**隔离复现：** 创建两个旧应用清理任务，执行第一个；创建不同 Helm 名称的新应用，确认 ID 相同；执行第二个任务，模拟卸载调用针对新 release，新应用的数据库记录也被删除。

**建议：** 任务绑定不可复用的资源 UUID，并持久化预期 release 名称；持锁后核对身份和状态版本，不匹配则拒绝执行。增加删除幂等约束。禁止主键复用可作为补充，不能代替任务与资源身份核验。

### S02 · P1 · SSH 文件传输接口仍允许读写服务端任意可访问路径

位置：[请求路径字段](../src/web/api/ssh.py#L51)、[上传路径传递](../src/web/api/ssh.py#L215)、[下载路径传递](../src/web/api/ssh.py#L268)、[SFTP 写本地文件](../src/core/ssh.py#L509)。

`local_path` 由请求提供，直接交给 `sftp.put/get`，没有服务端传输目录限制、路径归属核验或覆盖保护。这里的“本地”是 API 服务器，不是浏览器。RPM 默认以 root 运行，文件权限带来的限制很弱。

**触发条件：** 调用者已有有效登录令牌，且能连接一个通过主机密钥验证的 SSH 目标。这不是未登录漏洞，也没有绕过 SSH 主机身份校验。具备该条件后，可经上传接口读取服务端文件，经下载接口覆盖服务端配置、数据库或代码。

**隔离复现：** 使用真实 API 路由及 SFTP 调用链，只模拟 SSH 连接；下载接口覆盖临时测试目录中的指定文件，上传接口随后读取同一文件，两个请求均成功。没有访问实际配置或系统文件。

**建议：** 浏览器接口使用上传内容或服务端生成的文件 ID；本地文件限定到专用目录，并在打开时验证路径、链接与所有权。敏感文件访问与远程管理权限分别授权，不直接暴露任意宿主机路径。

### S03 · P1 · 未认证上传也会先占用临时磁盘

位置：[Chart 上传参数](../src/web/api/artifacts.py#L617)、[镜像上传接口](../src/web/api/artifacts.py#L980)、[鉴权装饰器](../src/web/utils/auth.py#L274)。

鉴权在端点装饰器执行时发生，FastAPI/Starlette 在此之前已解析 multipart 并接收文件。Chart 的 2 MB 检查同样在解析和鉴权之后；它不能限制未认证请求接收阶段的磁盘消耗。镜像上传也没有总上传字节、并发量与可用磁盘预算限制。

**隔离复现：** 无认证头上传 3 MiB 虚构 Chart 内容，监测到全部 3 MiB 已交给上传文件写入，再进入鉴权并返回 401。最终拒绝请求不能避免此前消耗资源。未实施磁盘耗尽或并发攻击。

**适用边界：** 直接访问内置 API，或入口网关未另行限制请求体时。外部网关策略未在本轮验证。

**建议：** 在读取上传请求体前完成认证；在入口和流式接收层设置可配置的字节、并发和时间限制，并为镜像大文件设置磁盘配额。不能只在 `UploadFile` 完成解析后检查大小。

### S04 · P1 · 并发续签产生的令牌不随登出撤销

位置：[请求处理前续签](../src/web/utils/auth.py#L322)、[返回续签令牌](../src/web/utils/auth.py#L343)、[只撤销请求令牌](../src/web/api/auth_routes.py#L54)、[按令牌哈希撤销](../src/core/orm/auth.py#L20)。

长请求通过鉴权并生成新令牌后，用户可同时登出。登出只撤销旧令牌；长请求随后仍返回新的有效令牌。前端已阻止迟到响应恢复本地会话，但这不能让后端拒绝那个新令牌。

**隔离复现：** 暂停一个已触发续签的请求，完成登出，再释放该请求。旧令牌被拒绝，迟到响应中的新令牌仍能通过真实 `get_current_user` 验证。

**建议：** 增加持久化登录会话标识；同一会话的所有续签共用会话身份，登出撤销会话及其后续令牌。续签应核验会话仍有效。仅让浏览器丢弃响应不能形成服务端撤销边界。

## 资源生命周期与本地数据保护

### S05 · P2 · 应用记录和任务创建不是一个事务，恢复也只扫描一次

位置：[部署入口的两次写入](../src/web/api/app.py#L205)、[集群记录提交](../src/core/orm/cluster.py#L232)、[恢复线程只在 worker 启动时执行](../src/cli/app.py#L163)。

创建应用记录成功、插入任务失败时，应用会永久留在 `pending`，没有任何可供恢复的任务。另一个断点是应用任务依赖 API 的 `BackgroundTasks` 执行，而通用任务恢复仅在 image-worker 启动时扫描一次；API 之后中断的任务不会由正在运行的 image-worker 持续领取。

**隔离复现：** 模拟任务插入失败，部署入口抛错后数据库仍存在新的 `pending` 应用，任务表为空。启动恢复的覆盖范围由调用链核实，未重启实际服务。

**建议：** 在同一事务中创建资源记录和任务，由持久化 worker 持续领取并恢复任务；HTTP 响应返回不应决定任务是否会被调度。

### S06 · P2 · 镜像导入先记成功，最终清理失败只写日志

位置：[完成任务与最终清理顺序](../src/web/api/artifacts.py#L909)。

`_finish_image_import_task()` 先写终态并释放租约，随后才执行最终 namespace 清理。清理失败只记 warning，任务仍显示成功，也没有可恢复的清理任务。没有下一次导入时，残留镜像会持续占用本地空间。

**隔离复现：** 导入和推送成功，首次清理成功，最终清理返回失败；持久化任务仍为 `success`，`error_message` 为空。

**建议：** 分开记录推送结果和清理结果，持久化 `cleanup_pending/failed` 及资源归属，允许单独重试清理；不要用笼统成功掩盖未完成的资源回收。

### S07 · P2 · 中断上传没有恢复终态，原始归档也没有保留上限

位置：[上传创建和文件复制](../src/web/api/artifacts.py#L945)、[只捕获普通异常](../src/web/api/artifacts.py#L965)、[worker 领取状态](../src/core/orm/image_import.py#L197)。

复制中断、请求任务取消或进程退出后，`uploading` 记录可能留下。worker 只领取 `pending/processing`，没有上传超时回收。普通复制失败后也未清理已写入的部分文件。成功、失败任务保留的原始大归档没有 TTL、容量配额或对应的清理入口。

**隔离复现：** 模拟复制阶段取消，记录保持 `uploading`，临时任务目录中保留文件，worker 无法领取该任务。文件保留策略缺失通过写入、领取及清理调用链确认。

**建议：** 上传采用临时文件与完成标记，增加上传心跳或截止时间；回收中断记录及部分文件。为原始归档制定可配置保留期和磁盘预算，保留供重试的文件时也应有明确归属和回收规则。

### S08 · P2 · 构建容器创建后挂载失败，不会进入清理

位置：[构建资源创建和 finally 范围](../src/builder/image/base_builder.py#L328)。

容器创建与挂载发生在负责清理的 `try/finally` 之前。`buildah from` 成功、`buildah mount` 失败或被中断时，已有容器没有被删除；重复构建会累积遗留容器。

**隔离复现：** 模拟创建返回容器 ID、挂载抛错，确认删除容器的回调从未执行。

**建议：** 取得容器 ID 后立即注册清理责任，覆盖挂载失败和取消；清理失败保留可查询的记录，便于后续回收。

### S09 · P2 · SQLite 文件未按敏感数据设置私有权限

位置：[数据库文件创建](../src/core/orm/engine.py#L7)、[保存应用配置和 Helm values](../src/core/orm/cluster.py#L224)。

数据库通过默认权限的 `touch()` 创建，没有像 JWT 密钥、应用 YAML 和运行锁文件一样限制为私有文件。在常见 `umask=022` 下，文件为 `0644`。应用配置和 Helm values 可能含业务密码；安装根目录和 config 目录可遍历时，同机其他账户能够读取。

**隔离复现：** 当前测试环境按默认创建逻辑生成的 SQLite 文件具有组和其他用户读权限。未读取生产数据库；实际机器是否能跨账户访问还取决于父目录权限和 ACL。

**建议：** 数据库目录和文件分别限制为服务账户专用权限，覆盖现有安装与 SQLite 的 journal/WAL/SHM 文件；同时防止链接替换，不仅保护 YAML 配置。

## 此前已指出、当前仍未完成的相关问题

- **R17：同步、缺少超时的上游 I/O。** 多个异步路由直接调用 requests/Kubernetes 客户端；Harbor `create_project` 等调用没有超时。上游卡住可以长期占住 Web worker，镜像任务也可能在持有 namespace 锁、持续续租的情况下停滞。参见 [Harbor 项目创建](../src/core/http_api_client/harbor_client.py#L357)、[Longhorn 请求](../src/core/http_api_client/longhorn_client.py#L53)。应设置连接/读取超时、总体任务期限，并将同步调用移出事件循环。
- **R16：通知仍限于单进程。** [ConnectionManager](../src/core/misc/websocket.py#L119) 明确只管理本进程连接，默认 Web worker 数量为 2。多进程通知一致性仍需共享事件传递或可靠的数据同步机制。本项不将此前已由用户确认的浏览器缓存现象重新判定为代码故障。
