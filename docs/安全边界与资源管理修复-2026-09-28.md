# 安全边界与资源管理修复

本次修改对应《项目设计审查》的安全边界、误初始化、删除失管和任务恢复问题。原审查文档保留修复前的证据，本文件记录修复后的行为及升级要求。

前端源码已在 `/opt/dashboard` 同步适配，详情见该工程的 `docs/auth-security-migration.md`。适配包括服务端登出、续签时间、WebSocket 会话切换及移除旧 AK/SK、内置密码登录。前端构建输出在 `/opt/dashboard/dist`，发布时应完整替换静态产物并移除旧免密登录文件；若管理员账号曾使用前端内置密码，应通过 `kubengine app set-password` 更换密码。

## 升级与恢复

1. **已有登录令牌会失效，需要重新登录。** `${root_dir}/config/jwt-signing.key` 首次生成后以 0600 保存；同一安装的 API 进程共用该文件及 SQLite 撤销记录。备份时将其作为秘密处理，不要放入发布包。
2. API 使用 Bearer Token。旧 AK/SK 认证已关闭，`kubengine app set-password` 只设置密码，不再生成不可用的 AK/SK。
3. 首次 SSH 纳管需要先通过可信渠道核验主机公钥，并写入执行端 known_hosts；引导文件可通过 `cluster config --known-hosts` 指定。详见 [SSH 与发布说明](security-bootstrap-release.md)。
4. **release 消失不能证明资源已删除。** 除确认尚未部署的 pending 记录外，找不到 release、查询失败、卸载超时或历史状态不明时都保留记录并报告错误。需要先核对 Kubernetes 中实际资源，再恢复管理状态；不会自动强删记录来消除错误。
5. 旧版 `api.app.deploy_app` 同时用于部署和删除，无法可靠判定意图。恢复时将该类任务标记失败并保留资源，需人工核对原操作后重新发起明确操作。
6. 同配置失败续跑仍受节点 guard 保护；部分初始化、API 无法访问等情况会停止并要求检查。配置变更不再隐式触发重装，不提供自动 reset。
7. 发布前提交经过审核的源码和匿名模板，使用安全归档脚本。构建脚本拒绝未提交的源码修改；未跟踪文件不会进入发布包。
8. **升级时停止 API 与 image-worker，确认旧进程退出后再统一启动新版本。** 任务锁位置和镜像任务执行接口已变化，不能让新旧版本同时运行。会自动沿用现有领取次数列，无新增数据库列；进行中的镜像任务通过租约到期恢复。

镜像操作使用本机 namespace 锁串行化。丢失租约时会停止后续步骤并拒绝旧状态写入，但不能撤回已经开始的外部推送；恢复可能再次推送同一镜像。锁会保留到当前执行结束及临时 namespace 清理完成，不会让新执行者与旧执行者同时清理同一 namespace。

## 验证范围及后续工作

最终全套回归：`env/bin/python -m pytest -q -o faulthandler_timeout=30`，**205 passed，7 warnings**。警告来自现有 Pydantic、Starlette 弃用接口。48 个修改或新增 Python 文件通过语法检查；`git diff --check` 和 `bash -n scripts/build_rpm.sh` 通过。

回归使用临时配置、临时数据库、假 SSH/Helm/kubeadm 命令和真实 ASGI 调用；没有对当前集群执行部署、删除、推送、SSH 或 RPM 安装。gevent 部署测试在独立进程运行，避免全局 monkey patch 污染 asyncio 和线程测试。

本次没有完成真实集群验收。控制面高可用、离线扩容完整性、RPM 完全离线依赖、跨进程 WebSocket 广播、Helm 表单值类型转换及完整部署状态版本化仍需后续专项处理。数据库与任务锁的协调范围是共享同一安装目录的进程，并非跨机器的分布式调度系统。
