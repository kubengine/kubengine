# 用户权限与操作审计使用指南

## 控制台使用

平台管理员通过“用户与授权”创建用户、修改角色、配置命名空间和敏感权限、启停账号及
重置密码。用户名与用户标识不可修改；不提供删除用户，退役账号使用停用。
系统拒绝停用或降权最后一个启用的平台管理员，并使用数据库写锁处理并发修改。
编辑冲突返回 409，需要刷新最新用户状态后重新配置。

所有用户可以通过“我的账户”查看当前角色、授权范围和敏感权限，刷新权限及修改
自己的密码。新密码至少 12 字符，UTF-8 最多 72 字节。停用、重新启用、本人改密和
管理员重置密码都会撤销旧会话；重新启用不会恢复旧令牌。角色、命名空间和敏感授权
在下一次后端请求生效，前端每 15 秒、窗口重新获得焦点或收到 403 时刷新授权。

| 角色 | 日常操作 |
| --- | --- |
| 平台管理员 | 用户、授权、审计、应用、制品、基础设施与集群资源管理；始终受 Kubernetes 连接身份的权限上限约束 |
| 命名空间运维 | 授权命名空间内普通资源查询、YAML 创建和修改；不能管理集群级对象、RBAC 或 ServiceAccount |
| 只读用户 | 授权命名空间内资源、状态、日志、事件和版本查询；无普通资源写入权限 |

普通用户“全部授权命名空间”只代表其明确绑定的集合，空集合不会回退为整个集群。
命名空间选项来自绑定名称；绑定可预先配置，资源实际不存在时集群仍可能返回 404。
集群总览、节点、制品、应用和管理员入口不向普通用户展示，直达 URL 同样校验。

## 敏感授权与工作负载边界

Secret 明文、Pod 终端、文件读取、文件修改是四项独立授权，只在已绑定命名空间内
有效。Secret 详情、YAML、预览、差异、快照使用一致的策略，未获明文权限时隐藏值
和注解；`reveal_secret=true` 不能代替授权。修改 Secret 还需要明文读取权限。

终端连接、输入及连接期间持续复核权限，Pod 终端的周期为 15 秒，平台通知连接为
30 秒，撤权后断开；不等待 JWT 到期。文件读取包含目录与下载，修改包含上传、
新建、重命名、删除。只有文件修改权限的账号可手动指定路径执行修改，无权列目录。
即使角色为只读，显式授予终端或文件修改也会赋予实际容器写能力。

普通运维用户的工作负载写入还须：

- 显式设置 `automountServiceAccountToken: false`。
- 默认只使用 `default` ServiceAccount；可在实际配置的
  `authorization.service_accounts.<namespace>` 中显式设置允许名称列表。
- 禁止 hostNetwork、hostPID、hostIPC、hostPath 和 hostPort。
- 普通容器、init 和 ephemeral 容器禁用提权、以非 root 运行，且不能增加 capabilities。
- 引用 Secret volume、projected Secret 或环境变量中的 Secret，还需要 `secret.read`。

示例配置：

```yaml
authorization:
  service_accounts:
    team-a: [default, restricted-app]
audit:
  retention_days: 90
```

这些应用侧校验不能替代 Kubernetes 准入。管理员必须按实际集群审查 Pod 安全准入、
可用镜像、ServiceAccount 权限、Secret/PVC 挂载、网络策略和配额，应用不会自动修改
客户集群策略。日志和普通配置本身也可能包含业务凭据，授予其读取权限前需评估。
共享 SDK 连接没有用户模拟能力，不提供 Kubernetes 用户级强多租户隔离。

## 审计查询与故障处理

管理员在“操作审计”按用户、时间、动作、命名空间、资源、请求编号、任务或批次筛选。
详情包含稳定用户 ID、可信连接来源、结果及版本/任务/上级事件关联。普通用户不能
查询、修改或删除审计。审计不保存密码、Token、Secret 值、文件内容或终端输入/输出。
来源使用服务器已解析的连接地址，只有服务器显式信任的代理链才可参与来源解析。

写操作执行前必须成功保存 pending 事件，否则返回 503 且不执行。操作可能已生效但
审计收尾失败时，返回 `AUDIT_FINALIZE_UNCERTAIN`、审计编号和“操作结果待核实”，
应先按请求编号查询审计、任务和资源，禁止盲目重试。进程中断可能留下 pending，
应核对外部状态，不把它解释为“未执行”。

任务保存发起者 ID、凭据版本、请求编号和父审计事件，在开始与新外部步骤前复核。
账号停用、改密或降权后停止后续受限操作，保留已完成步骤和检查点；任务记为失败，
不自动回滚已生效的集群变更。缺少身份的旧任务拒绝自动执行，应由管理员核对后
明确重新提交。镜像维护使用系统身份，只能处理对应任务的临时 containerd namespace，
不会代替已撤权用户继续推送或部署。

## 保留与归档

默认保留窗口 90 天，可用 `audit.retention_days` 配置。本期不静默自动删除审计；
管理员可通过本机受控命令定期执行归档，先查看结果，再决定是否清理：

```bash
kubengine app audit-archive
kubengine app audit-archive --prune
```

命令把超过窗口、已结束的事件写入 `${root_dir}/config/audit-archives`，目录 0700、
文件 0600；生成 JSONL 和 SHA-256，完成 fsync 并重读校验后才可清理对应数据库行。
pending 记录保留供核实。归档与数据库备份均包含身份与资源元信息，应限制访问。
应用层追加记录不能防止数据库管理员篡改，不应宣传为防篡改审计。

## 迁移、备份与恢复

首次迁移原样保留实际配置中用户的 bcrypt 哈希，导入为平台管理员并写入幂等完成
标记。之后数据库为唯一认证来源，修改或保留旧配置不会覆盖、补入或恢复账号。
既有 identity-v1 安装直接保留用户标识与授权，本版新增审计表和任务 auth_context 列。

更新前核对实际配置路径、root_dir、版本与两个服务，排空或盘点待执行任务；停止
API/worker 后备份代码、静态资源、配置、SQLite、JWT 和 YAML 历史密钥。运行中备份
数据库应使用 SQLite backup API，不应只复制 WAL 模式的主文件。

恢复时停止全部写入者，将数据库、对应密钥与配置恢复到隔离目录，运行幂等迁移并
验证稳定用户 ID、角色/范围/敏感授权、停用状态、管理员原密码及会话撤销行为。
验证后才能切回正式路径；不能通过删除数据库重新导入配置用户作为普通修复手段。

回滚到没有本版授权的旧程序前，先限制普通用户访问并停止 worker，否则旧接口可能
扩大其权限。必须使用同一时点的数据库/配置/密钥；恢复整库前评估升级后新增业务
数据，避免丢失已完成操作。

最小连接权限示例见[专用服务账号示例](kubernetes-console-serviceaccount.yaml)，
设计依据见[用户权限与审计设计](用户权限与审计设计.md)。
