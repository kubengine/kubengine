# Kubernetes 手动离线部署文档（不依赖 KubEngine）

## 1. 适用范围

本文档用于在 **Kylin Server V11 x86_64** 上手动部署 Kubernetes 及配套组件。整个过程不安装 KubEngine，不调用 `kubengine` 或 `kubengine-k8s`，仅使用 Linux 系统命令、`kubeadm`、`kubectl`、`ctr` 和 `helm`。

本文档仍使用 `offline-deploy.tgz` 中的 RPM、镜像、Chart 和模板。它们只是离线制品，不需要 KubEngine 程序才能使用。

| 组件 | 版本 |
| --- | --- |
| Kubernetes | v1.34.0 |
| containerd | 2.1.3 |
| CNI plugins | v1.7.1 |
| Kata Containers | 3.18.0 |
| Calico | v3.27.0 |
| MetalLB | v0.15.2 |
| Ingress NGINX | v1.13.3 |
| Longhorn | v1.9.1 |
| Harbor | v2.14.0 |
| Metrics Server | v0.8.0 |
| cert-manager | v1.16.3 |

## 2. 部署规划

下文以三节点为例，请先按实际环境替换所有 IP、网卡名和域名。

| 角色 | 主机名 | IP |
| --- | --- | --- |
| Master | `master01` | `172.31.96.11` |
| Worker | `node01` | `172.31.96.12` |
| Worker | `node02` | `172.31.96.13` |

| 项目 | 示例值 |
| --- | --- |
| Pod CIDR | `10.96.0.0/16` |
| Service CIDR | `10.97.0.0/16` |
| MetalLB 地址池 | `172.31.57.30-172.31.57.40` |
| 平台域名 | `kubengine.io` |
| 离线目录 | `/root/offline-deploy` |

Pod CIDR、Service CIDR 不能与宿主机网段重叠；MetalLB 地址不能被 DHCP 或其他设备占用。

## 3. 分发离线包

先在运维机解压，再将完整目录复制到每个节点的相同路径：

```bash
tar -zxf offline-deploy.tgz -C /root/
scp -r /root/offline-deploy root@172.31.96.11:/root/
scp -r /root/offline-deploy root@172.31.96.12:/root/
scp -r /root/offline-deploy root@172.31.96.13:/root/
```

每个节点检查：

```bash
DEPLOY_DIR=/root/offline-deploy
test -d "$DEPLOY_DIR/repo"
test -f "$DEPLOY_DIR/containerd/containerd-2.1.3-linux-amd64.tar.gz"
test -f "$DEPLOY_DIR/containerd/runc.amd64"
test -f "$DEPLOY_DIR/cni-plugins-linux-amd64-v1.7.1.tgz"
test -f "$DEPLOY_DIR/images/kubenetes.images.v1.34.0.tar.gz"
test -f "$DEPLOY_DIR/images/calico.images.v3.27.0.tar.gz"
```

> 现有离线包的 Kubernetes 镜像文件名确为 `kubenetes.images.v1.34.0.tar.gz`，请不要自行改名。

## 4. 初始化所有节点

本章命令需在所有 Master 和 Worker 节点上以 root 执行。

### 4.1 主机名与 hosts

在各节点分别执行 `hostnamectl set-hostname master01`、`node01` 或 `node02`。所有节点的 `/etc/hosts` 均加入：

```text
172.31.96.11 master01
172.31.96.12 node01
172.31.96.13 node02
```

### 4.2 系统参数

```bash
swapoff -a
sed -ri '/\sswap\s/s/^#?/#/' /etc/fstab
systemctl disable --now firewalld
setenforce 0 || true
sed -ri 's/^SELINUX=.*/SELINUX=disabled/' /etc/selinux/config

cat >/etc/modules-load.d/kubernetes.conf <<'EOF'
overlay
br_netfilter
EOF
modprobe overlay
modprobe br_netfilter

cat >/etc/sysctl.d/99-kubernetes-cri.conf <<'EOF'
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sysctl --system
```

生产环境如不允许关闭防火墙，需完整放行 Kubernetes、Calico、VRRP、Longhorn、Ingress 及对外 Service 所需端口。

### 4.3 时间同步

纯内网可以让 `master01` 作为 NTP 服务端。在 `master01` 执行：

```bash
cat >/etc/chrony.conf <<'EOF'
driftfile /var/lib/chrony/drift
makestep 1.0 3
rtcsync
allow 172.31.96.0/24
local stratum 10
logdir /var/log/chrony
EOF
systemctl enable --now chronyd
chronyc makestep
```

其他节点执行：

```bash
cat >/etc/chrony.conf <<'EOF'
server 172.31.96.11 iburst
driftfile /var/lib/chrony/drift
makestep 1.0 3
rtcsync
logdir /var/log/chrony
EOF
systemctl enable --now chronyd
chronyc makestep
chronyc tracking
```

## 5. 安装 CNI、containerd 和 Kata

所有节点执行：

```bash
DEPLOY_DIR=/root/offline-deploy
install -d /opt/cni/bin /etc/cni/net.d
tar -zxf "$DEPLOY_DIR/cni-plugins-linux-amd64-v1.7.1.tgz" -C /opt/cni/bin

dnf remove -y containerd || true
install -d /opt/containerd /etc/containerd /etc/kata-containers
tar -zxf "$DEPLOY_DIR/containerd/containerd-2.1.3-linux-amd64.tar.gz" -C /opt/containerd
install -m 0755 "$DEPLOY_DIR/containerd/runc.amd64" /usr/local/bin/runc
ln -sfn /opt/containerd/bin/containerd-shim-runc-v2 /usr/local/bin/containerd-shim-runc-v2
ln -sfn /opt/containerd/bin/ctr /usr/local/bin/ctr

tar -zxf "$DEPLOY_DIR/containerd/kata-static-3.18.0-amd64.tar.gz" -C /opt
ln -sfn /opt/kata/bin/containerd-shim-kata-v2 /usr/local/bin/containerd-shim-kata-v2
ln -sfn /opt/kata/bin/kata-runtime /usr/local/bin/kata-runtime
ln -sfn /opt/kata/share/defaults/kata-containers/configuration.toml \
  /etc/kata-containers/configuration.toml

install -m 0644 "$DEPLOY_DIR/containerd/config.toml" /etc/containerd/config.toml
tar -zxf "$DEPLOY_DIR/containerd/certs.d.tar.gz" -C /etc/containerd
```

确认 `/etc/containerd/config.toml` 中 CRI 未被禁用、`SystemdCgroup = true`，registry `config_path` 指向 `/etc/containerd/certs.d`。然后创建服务：

```bash
cat >/usr/lib/systemd/system/containerd.service <<'EOF'
[Unit]
Description=containerd container runtime
After=network.target
[Service]
ExecStartPre=/sbin/modprobe overlay
ExecStart=/opt/containerd/bin/containerd
Delegate=yes
KillMode=process
[Install]
WantedBy=multi-user.target
EOF
systemctl daemon-reload
systemctl enable --now containerd
ctr version
```

## 6. 安装 Kubernetes

### 6.1 所有节点安装 RPM 并导入镜像

```bash
DEPLOY_DIR=/root/offline-deploy
cat >/etc/yum.repos.d/kubernetes-offline.repo <<EOF
[kubernetes-offline]
name=Kubernetes Offline Repository
baseurl=file://$DEPLOY_DIR/repo
enabled=1
gpgcheck=0
EOF

dnf --disablerepo='*' --enablerepo=kubernetes-offline install -y \
  kubelet kubeadm kubectl

cat >/etc/crictl.yaml <<'EOF'
runtime-endpoint: unix:///var/run/containerd/containerd.sock
image-endpoint: unix:///var/run/containerd/containerd.sock
timeout: 10
debug: false
EOF
systemctl enable --now kubelet

ctr -n k8s.io images import "$DEPLOY_DIR/images/kubenetes.images.v1.34.0.tar.gz"
ctr -n k8s.io images import "$DEPLOY_DIR/images/calico.images.v3.27.0.tar.gz"
```

### 6.2 初始化 Master

在 `master01` 执行：

```bash
kubeadm init \
  --apiserver-advertise-address=172.31.96.11 \
  --control-plane-endpoint=172.31.96.11 \
  --kubernetes-version=v1.34.0 \
  --service-cidr=10.97.0.0/16 \
  --pod-network-cidr=10.96.0.0/16 \
  --upload-certs \
  --ignore-preflight-errors=all

install -d /root/.kube
install -m 0600 /etc/kubernetes/admin.conf /root/.kube/config
echo 'export KUBECONFIG=/etc/kubernetes/admin.conf' >>/etc/profile
export KUBECONFIG=/etc/kubernetes/admin.conf
```

> `--ignore-preflight-errors=all` 是为了与现有离线部署流程保持一致。生产环境建议先不加该参数执行，根据 preflight 结果修复所有错误，而不是直接忽略。

如需让 Master 也调度业务 Pod：

```bash
kubectl taint nodes --all node-role.kubernetes.io/control-plane:NoSchedule-
```

### 6.3 Worker 加入

在 Master 生成命令：

```bash
kubeadm token create --print-join-command
```

将输出的完整 `kubeadm join ...` 命令复制到每个 Worker 执行。

### 6.4 安装 Calico

在 Master 执行：

```bash
DEPLOY_DIR=/root/offline-deploy
install -d /root/manifests
cp "$DEPLOY_DIR/templates/calico.yaml.j2" /root/manifests/calico.yaml
sed -i 's#{{[[:space:]]*pod_network_cidr[[:space:]]*}}#10.96.0.0/16#g' \
  /root/manifests/calico.yaml
grep -n '{{\|}}' /root/manifests/calico.yaml || true
kubectl apply -f /root/manifests/calico.yaml
kubectl get pods -n kube-system -w
```

`grep` 应当无输出；如仍有模板变量，需手动填充后再 apply。最后确认所有节点为 `Ready`：

```bash
kubectl get nodes -o wide
kubectl get pods -A
```

## 7. 高可用控制面（可选）

单 Master 跳过本章。高可用模式下，所有 Master 安装 Keepalived：

```bash
dnf --disablerepo='*' --enablerepo=kubernetes-offline install -y keepalived
```

以 VIP `172.31.96.100`、网卡 `ens31` 为例，第一个 Master 的 `/etc/keepalived/keepalived.conf` 为：

```text
global_defs {
    router_id LVS_K8S
    script_user root
    enable_script_security
}
vrrp_instance VI_K8S_APISERVER {
    state MASTER
    interface ens31
    virtual_router_id 51
    priority 100
    advert_int 2
    authentication {
        auth_type PASS
        auth_pass 42f8a7c3
    }
    virtual_ipaddress {
        172.31.96.100/24
    }
}
```

其他 Master 使用 `state BACKUP`，priority 依次使用 95、90。各节点执行：

```bash
systemctl enable --now keepalived
ip addr show ens31 | grep 172.31.96.100
```

VRRP 需放行 IP 协议号 112。`virtual_router_id` 在同一二层网络内必须唯一。生产环境建议再配置 API Server 健康检查脚本。

初始化第一个 Master 时将 `--control-plane-endpoint` 设为 `172.31.96.100`。随后在第一个 Master 执行：

```bash
kubeadm token create --print-join-command
kubeadm init phase upload-certs --upload-certs
```

在附加 Master 执行：

```bash
kubeadm join 172.31.96.100:6443 \
  --control-plane \
  --certificate-key '<certificate-key>' \
  --token '<token>' \
  --discovery-token-ca-cert-hash 'sha256:<hash>' \
  --ignore-preflight-errors=all
```

Worker 也应通过 VIP join。certificate key 过期后需重新执行 `upload-certs`。

## 8. 安装 Helm 并导入扩展镜像

Master 安装 Helm：

```bash
install -m 0755 /root/offline-deploy/helm /usr/local/bin/helm

```

为避免 DaemonSet 或容忍控制面污点的 Pod 落到缺失镜像的节点，以下命令需在所有集群节点执行：

```bash
  metallb.images.v0.15.2.tar.gz \
  ingress-nginx.images.v1.13.3.tar.gz \

done
```

## 9. 生成 TLS 证书

在 Master 生成覆盖主域名和泛域名的自签证书：

```bash
install -d -m 0700 /root/platform-certs
cd /root/platform-certs
openssl genrsa -out ca.key 4096
openssl req -x509 -new -sha256 -days 3650 -key ca.key -out ca.crt \
  -subj '/C=CN/ST=Beijing/L=Beijing/O=platform/CN=platform root ca'
openssl genrsa -out server.key 4096
openssl req -new -key server.key -out server.csr \
  -subj '/C=CN/ST=Beijing/L=Beijing/O=platform/CN=kubengine.io'
cat >server.ext <<'EOF'
basicConstraints=critical,CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth,clientAuth
subjectAltName=DNS:kubengine.io,DNS:*.kubengine.io
EOF
openssl x509 -req -sha256 -days 3650 \
  -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out server.crt -extfile server.ext
openssl verify -CAfile ca.crt server.crt
chmod 0400 ca.key server.key
```

将 `ca.crt` 分发到所有集群节点及管理端，然后执行：

```bash
install -m 0644 ca.crt /etc/pki/ca-trust/source/anchors/platform-ca.crt
update-ca-trust
```

`kubengine.io` 只是当前 Chart 的默认域名，不代表对 KubEngine 程序的依赖。如改用其他域名，需同时修改证书 SAN、Chart values 和 DNS/hosts。

## 10. 安装平台组件

以下命令均在 Master 执行。每安装一个组件，建议先等待 Pod 正常再继续。

### 10.1 渲染 Chart 模板

部分 Chart 使用 `values.yaml.j2`/`Chart.yaml.j2`。需先生成最终文件：

```bash
DEPLOY_DIR=/root/offline-deploy
DOMAIN=kubengine.io
for component in longhorn harbor kuboard kubernetes-dashboard; do
  dir="$DEPLOY_DIR/charts/$component"
  test -f "$dir/values.yaml.j2" && cp "$dir/values.yaml.j2" "$dir/values.yaml"
  sed -i "s#{{[[:space:]]*domain[[:space:]]*}}#$DOMAIN#g" "$dir/values.yaml"
done

DASHBOARD_DIR="$DEPLOY_DIR/charts/kubernetes-dashboard"
if test -f "$DASHBOARD_DIR/Chart.yaml.j2"; then
  cp "$DASHBOARD_DIR/Chart.yaml.j2" "$DASHBOARD_DIR/Chart.yaml"
  sed -i "s#{{[[:space:]]*domain[[:space:]]*}}#$DOMAIN#g" "$DASHBOARD_DIR/Chart.yaml"
fi
grep -RIn '{{\|}}' "$DEPLOY_DIR/charts" --include='*.yaml' || true
```

最后一条命令应当无输出；如仍有结果，先按实际环境填充剩余变量。

### 10.4 Longhorn

所有会运行 Longhorn 的节点执行：

```bash
dnf --disablerepo='*' --enablerepo=kubernetes-offline install -y open-iscsi
echo "InitiatorName=$(/sbin/iscsi-iname)" >/etc/iscsi/initiatorname.iscsi
systemctl enable --now iscsid
for module in uio_pci_generic vfio_pci iscsi_tcp; do
  modprobe "$module"
  echo "$module" >"/etc/modules-load.d/$module.conf"
done
```

如使用独立数据盘，先用 `lsblk -f` 确认设备。下列命令会格式化 `/dev/vdc`，**会删除该盘现有数据**：

```bash
mkfs.ext4 /dev/vdc
install -d /var/lib/longhorn
LONGHORN_UUID=$(blkid -s UUID -o value /dev/vdc)
echo "UUID=$LONGHORN_UUID /var/lib/longhorn ext4 defaults 0 0" >>/etc/fstab
mount -a
findmnt /var/lib/longhorn
```

Master 执行：

```bash
kubectl create namespace longhorn-system --dry-run=client -o yaml | kubectl apply -f -
kubectl -n longhorn-system create secret tls longhorn-tls \
  --cert=/root/platform-certs/server.crt --key=/root/platform-certs/server.key
helm install longhorn "$DEPLOY_DIR/charts/longhorn" \
  -n longhorn-system -f "$DEPLOY_DIR/charts/longhorn/values.yaml"
```

## 12. 验收与排错

```bash
kubectl get nodes -o wide
kubectl get pods -A -o wide
kubectl get svc,ingress -A
kubectl get storageclass
kubectl get pv,pvc -A
kubectl top nodes
```

验收标准：所有节点为 `Ready`；核心 Pod 和所选组件为 `Running`；Ingress Controller 获得 `172.31.57.30`；域名可解析；管理端信任自签 CA。

快速定位异常：

```bash
kubectl get pods -A --field-selector=status.phase!=Running,status.phase!=Succeeded
kubectl get events -A --sort-by='.lastTimestamp' | tail -100
journalctl -u kubelet -n 200 --no-pager
journalctl -u containerd -n 200 --no-pager
```

### ImagePullBackOff

```bash
kubectl describe pod -n <namespace> <pod-name>
ctr -n k8s.io images list | grep '<image-keyword>'
```

离线镜像的完整引用（registry/repository:tag）必须与 Pod spec 一致。镜像 ID 相同但引用名不同时，containerd 仍可能尝试连网拉取。

### 节点 NotReady

```bash
kubectl describe node <node-name>
journalctl -u kubelet -f
ls -al /etc/cni/net.d /opt/cni/bin
```

重点检查 Calico、Pod CIDR、IP forwarding、containerd CRI 和 cgroup 配置。

### Helm 安装失败

```bash
helm list -A
helm status <release> -n <namespace>
```

删除 release 前先检查 PVC 和已写入数据。Harbor、Longhorn 等有状态组件不应盲目删除 namespace 或 PVC。

## 13. 备份建议

部署完成后至少备份：

- `/etc/kubernetes/` 和 kubeconfig；
- etcd 快照；
- `/root/platform-certs/` 中的 CA 和服务器证书；
- 实际使用的 Helm values 和 `/root/manifests/`；
- Longhorn 卷备份；
- Harbor 数据库、registry 数据和配置；
- 离线包版本及校验和。
