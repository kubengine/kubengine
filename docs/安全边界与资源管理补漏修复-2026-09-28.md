# 安全边界与资源管理补漏修复

对应[复查报告](安全边界与资源管理复查-2026-09-28.md)中的 S01–S09，并补齐此前 R16 的跨进程状态通知和 R17 的外部请求超时。修改集中在后端；前端现有 Bearer、登出和 `refresh_clusters` 协议继续适用，本轮未修改 `/opt/dashboard`。

后续的应用租约、检查点恢复、提交幂等及 dashboard 配套修改见[统一任务恢复与部署幂等](统一任务恢复与部署幂等-2026-09-28.md)。

## 修复结果

| 项目 | 当前行为 |
| --- | --- |
| S01 旧清理任务误删新资源 | 集群拥有独立 UUID；任务入队时绑定 UUID 和 Helm release，执行时持资源锁核对。重复删除复用未完成任务；身份不符、缺少身份的旧任务明确失败，保留资源。 |
| S02 SSH 任意服务端文件读写 | Web 接口的 `local_path` 只接受单个文件名，限定在当前用户专属目录。目录 0700、文件 0600，拒绝符号链接、硬链接和覆盖；通过持有的文件描述符传给 SFTP，失败删除此次新建文件。CLI 文件传输保持原有管理员操作能力。 |
| S03 未认证上传提前占用磁盘 | 在 multipart 解析之前鉴权；限制请求体实际字节、单文件大小、文件/字段数、上传时间、跨进程并发及临时盘余量。未知长度的流式请求同样受限。解析失败、断连、取消均关闭 spool 文件。 |
| S04 并发续签绕过登出 | 登录创建持久化会话 `sid`，续签沿用会话；登出撤销整个会话。先于登出生成、迟到返回的令牌也不能继续认证。 |
| S05 入队断裂和恢复遗漏 | 应用记录与部署任务同事务提交。独立 worker 持续轮询应用任务，线程池有并发上限，恢复不依赖 HTTP BackgroundTasks；锁忙时保留任务，轮询兼顾后续任务。 |
| S06 镜像清理失败被当作成功 | 新任务使用独立 containerd namespace；清理镜像及 namespace 结束后才释放租约并设置终态。失败持久化 `cleanup_pending`、错误和重试时间，任务显示失败但保留已成功的镜像明细；后台重试只做清理，不重复推送成功镜像。 |
| S07 上传中断和归档无界保留 | 服务端固定归档文件名，私有目录及原子完成写入；限制单文件、归档总额和磁盘余量。取消时等待写入退出再关闭文件；worker 回收超时 uploading 和过期终态归档。临时文件删除失败会保留恢复路径。配额扫描与回收共用锁。 |
| S08 挂载失败泄漏构建容器 | 容器创建后的挂载已纳入 `finally` 清理范围，挂载失败也执行卸载和删除。 |
| S09 数据库权限过宽 | 启动收紧 config 目录为 0700，数据库及已有 journal/WAL/SHM 为 0600；检查所有者、普通文件和单硬链接，拒绝链接路径。 |
| R16 跨进程通知 | 数据库保存集群变更 revision，各 API 进程每 0.5 秒检查并向本进程 WebSocket 广播刷新。独立 worker 产生的变更可到达任意 API 进程。 |
| R17 外部 IO 无超时 | Harbor、Dashboard、Longhorn 的普通 HTTP 请求使用连接/读取超时 5/30 秒，已有短轮询保留原超时；Kubernetes 查询同样限时，健康轮询增加总等待截止时间。同步业务端点进入线程池，Chart 推送限时 600 秒。 |

## 升级步骤和兼容性

1. 停止 API 和 `kubengine-image-worker`，确认旧进程退出后统一更新后端代码，再启动两个服务。不要混跑新旧版本。数据库表、集群 UUID 和镜像清理字段在启动时自动创建或补齐。
2. **所有旧登录令牌需要重新登录**：没有持久化 `sid` 的令牌会被拒绝。会话表不保存明文令牌。
3. 缺少资源 UUID/预期 Helm 名称的旧应用任务不会自动执行。核实原任务意图和现有 release 后重新提交操作；不要给旧任务直接补写当前资源身份来强行恢复。
4. 应用部署/删除和镜像任务均需独立 worker 运行。RPM 使用 `kubengine-image-worker.service`；手工环境运行 `kubengine app image-worker`。原名称保持不变，worker 现在同时负责应用队列及资源维护。
5. 已有镜像任务没有 namespace 字段时沿用旧 `apps` namespace，并继续受同一全局镜像锁保护；新任务使用 `kubengine-import-<任务 ID>`。旧任务清理不会删除共享 `apps` namespace 本身。
6. Web SSH 传输的 `local_path` 不再接受绝对路径或目录。专属目录为 `${root_dir}/tmp/ssh-transfers/<用户名 UTF-8 的 SHA-256 十六进制>/`。下载只创建新文件；上传读取该目录中的已有文件，管理员预置文件也必须由服务用户所有、权限 0600、非链接。响应仅返回文件名。
7. 归档过期后，镜像任务和每个镜像结果仍保留；重试需要重新上传归档，原任务重试返回 410。清理尚未完成的归档暂不按保留期删除，但仍计入容量上限。

## 上传配额

在实际加载的配置中设置 `security.uploads`，未设置时使用以下默认值。匿名示例已更新到 `config/application.example.yaml`，没有覆盖现有运行配置。

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `image_bytes` | 10737418240 | 单个镜像归档 10 GiB；Chart 固定 2 MiB |
| `archive_bytes` | 53687091200 | 留存镜像归档总计 50 GiB |
| `reserve_bytes` | 1073741824 | 临时盘、归档盘预留 1 GiB |
| `concurrency` | 2 | 同一安装所有 API 进程的上传总并发 |
| `timeout_seconds` | 3600 | 请求体接收/归档保存期限及中断上传回收阈值 |
| `retention_seconds` | 604800 | 已结束且清理完成的归档保留 7 天 |

超出单文件或请求体限制返回 413；上传并发占满返回 429；空间或归档配额不足返回 507；接收超时返回 408。所有配置必须为正整数。维护循环约每 30 秒运行，清理失败默认至少间隔 60 秒再试。
