# HTTP、兼容路由与任务入口清单

本清单与 `用户权限与审计设计.md` 配套，按当前路由声明清点；新增路由必须同步权限与审计设计。
路径参数均不能作为可信授权上下文，身份由服务端认证取得。

当前 RBAC 版本：资源查询、YAML 与 Pod 操作按动作、类型和命名空间授权；其他业务默认管理员。
普通平台通知 WebSocket 仅管理员，Pod 终端使用独立敏感授权；所有入口纳入审计。

Deployment 运维增量接口（均为 `/api/v1/k8s/deployments/{namespace}/{name}` 前缀）：
GET `/operations`、`/operations/{operation_id}` 使用 resource.read；POST `/scale`、`/restart`
使用 resource.update，并固定授权目标为 Deployment。后台独立操作表和租约每次复核发起者，
不使用默认仅管理员可见的通用任务接口。执行审计为 deployment.scale/deployment.restart，
HTTP 受理审计为 deployment.scale.submit/deployment.restart.submit，关联操作与加密版本。
完整行为、未知结果和权限撤销处置见 [Deployment 运维](Deployment运维.md)。

## 实际资源与异步执行路径

| 入口/执行器 | 实际访问路径 | 计划权限与审计 |
| --- | --- | --- |
| `k8s.py` | `KubernetesViewClient` → SDK core/apps/batch/networking/storage/RBAC/custom/metrics API；overview 同时读取 Longhorn | namespace 资源按授权集合过滤后再统计、搜索和分页；node/overview/Longhorn 管理员 |
| `resource_yaml.py` 编辑/版本 | `ResourceYaml` → SDK GET/PATCH；`resource_yaml_revision` 加密快照与差异 | resource.read/write + Secret 明文额外授权；resource.preview/apply/history |
| `resource_yaml.py` 批量创建 | `ResourceCreator.targets` → discovery → 动态 namespaced/cluster API → dry-run → create | 逐项解析真实 GVK、范围、动作；全部授权成功才允许任何写入；resource.create.batch |
| Pod 文件 | `PodOperations` → SDK pods/exec → 容器内脚本/流式下载 | read/write 分开；download 在首字节前检查；pod.file.* |
| Pod terminal | 首条 auth 消息 → `PodOperations.exec_session`；后台 bridge 线程执行 stdin/resize | pod.terminal；连接期间每 15 秒及输入前复核；terminal.connect/disconnect |
| 普通 `/ws` | connection_manager；跨进程 revision 轮询广播应用/集群变化 | 管理员；每次广播/回复和每 30 秒复核；不向普通用户广播 |
| 应用管理 | `app.py` → Helm、cluster/submission/task ORM → `core/deployment.py` 等编排 | 平台管理员；app.config/deploy/retry/delete；查询也仅管理员 |
| 应用 worker | `AppTaskWorker.poll` → `find_unfinished_tasks` → `execute_task_function` → lease/phase → task_func_path | auth_context 保存稳定发起者与请求/审计关联；开始及外部步骤前复核 |
| 镜像导入/重试 | multipart → `create_image_import_task` → `TaskWorker` → `process_image_import_task` → containerd/registry/SSH；维护线程清理 namespace | 平台管理员；image.import/retry/cleanup；任务与清理都要继承身份 |
| Helm chart 上传与制品变更 | Harbor HTTP、Helm CLI、临时文件/目录 | 平台管理员；artifact.upload/delete/tag |
| SSH/基础设施 | `ssh.py` → 主机连接、命令执行、文件传输 | 平台管理员；infra.execute/upload/download；不记录命令正文、密钥或文件内容 |
| `/create-resource` | FastAPI BackgroundTasks → `create_resource_task`（当前模拟任务，不写 Kubernetes） | 平台管理员；仍纳入任务身份上下文与审计，禁止作为未鉴权入口 |
| CLI `set-password` | `reset_admin_password` → DB + 撤销全部 admin 会话 | 本机已有系统权限入口；使用 local-cli 系统身份审计，不允许重新启用停用 admin |

## 特殊参数与敏感内容

- `dashboard/resource`、`dashboard/resourcedetail`、`dashboard/resourcepod` 与新路由使用相同权限。
- `_all`、`_cluster`、空 namespace、缺省 namespace、大小写/复数 kind 和 URL 编码必须先规范化再鉴权。
  普通用户“全部”仅表示其授权集合；cluster scope 拒绝，不能把 `_cluster` 当成可授权的普通 namespace。
- Secret 列表/详情的 `data`、`stringData`、annotations、YAML、预览、快照及 diff 都需要统一明文策略。
  所有资源入口使用统一权限服务，不能以脱敏或前端隐藏代替后端授权。
- 日志属于 namespace 普通读取，但内容可能含业务凭据；应在使用说明中明确这一授权边界。
  文件目录和下载需要 `pod.files.read`，上传和 mkdir/rename/delete 需要 `pod.files.write`；
  终端单独需要 `pod.terminal`，不自动蕴含文件 API 权限。

`tests/test_authorization_audit.py` 覆盖权限允许/拒绝矩阵、任务撤权和审计故障。

新增 `GET /api/v1/audit-events` 提供管理员审计查询；CLI `audit-archive` 仅本机归档和显式清理。
